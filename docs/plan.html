Level 3 Sakila Dates Filling gaps Пример будущей страницы

Count rentals per month, including months with no rentals at all

В Sakila прокаты есть с мая по август 2005 года и в феврале 2006-го. Месяцы между ними должны попасть в отчёт с нулём, а обычный GROUP BY их просто не покажет.

Чем решения отличаются

A · generate_seriesB · recursive CTE
Результат АВТООдинаковый: 10 строк, с мая 2005 по февраль 2006, пять месяцев с нулём
Скорость АВТОЧитает всю таблицу: date_trunc() над колонкой не даёт использовать индекс по rental_dateИспользует индекс по rental_date. На Sakila быстрее A примерно в 1,5 раза: отчёт всё равно читает почти все строки. Разница вырастет, если запросить узкий период
ЧитаемостьКороче и понятнееДлиннее: месяцы генерируются вручную
MySQLне работает generate_series нетпочти так же меняется запись интервала
ВыводДля разового отчёта в PostgreSQL подойдёт A. Если таблица большая или нужен перенос в MySQL, бери B.

Указываем источник

Как гарантируем, что задачи без ошибок

Вручную это не проверить. Каждая задача проходит автоматическую проверку при каждом изменении.

  1. ЧерновикЗадача и 1–4 решения в файле. Пишу я, партиями по датасету и уровню.
  2. PostgreSQLВсе решения запускаются в PGlite. Ошибка — проверка падает.
  3. Сверка решенийВсе варианты обязаны дать один и тот же результат, или различие помечено и объяснено.
  4. MySQL 8.4MySQL-варианты запускаются в Docker на той же базе, результат сверяется с PostgreSQL.
  5. ЗамерыПлан и время каждого решения сохраняются для таблицы сравнения.
  6. Твоя ревизияТы решаешь выборку задач сам. Что непонятно — правим.
  • У каждого датасета одна копия данных, из которой собираются обе версии. Готовые «порты» не берём вслепую: свежая Pagila, например, уже разошлась с Sakila по датам и количеству строк.
  • У каждой задачи есть хотя бы одна ссылка на официальную документацию.
  • Ответы детерминированы: при равенствах указан полный порядок сортировки, иначе проверка будет «плавать».
  • Проверка запускается в GitHub Actions на каждый коммит. Сломанная задача не попадёт на сайт.

    Согласовать план

    • Карта тем, список датасетов, формат задачи — эта страница
  2. Этап 1 · готово

    Фундамент

    • Формат задачи: несколько решений, MySQL-вариант, ссылки на документацию
    • Загрузка датасета по требованию, а не всех сразу
    • Страница задачи с переключением решений и СУБД, таблица сравнения
    • Автопроверка всех решений в PGlite
    • Chinook и Sakila, по 30 задач на каждую
    • Сборка датасетов: одни и те же данные загружаются и в PostgreSQL, и в MySQL

    Итог: 60 задач (30 Sakila + 30 Chinook, уровни 1–3), 30 из них с 2–4 решениями (всего 96 решений, 8 из них только для PostgreSQL). Все 60 проходят проверку на PostgreSQL 18.6 и MySQL 8.4.11. Обе базы собраны из официальных исходников и совпадают построчно.

  3. Этап 2 · готово

    Проверка на MySQL

    • MySQL 8.4 в Docker, MySQL-версии датасетов
    • Сверка MySQL-решений с PostgreSQL, запуск в GitHub Actions

    Итог: репозиторий github.com/Kirill-2112/sql-playbook. На каждый push GitHub Actions собирает обе базы из официальных исходников, сверяет их построчно и проверяет все 80 задач на PostgreSQL 18.6 и MySQL 8.4.11.

  4. Этап 3 · сейчас

    Масштаб

    • Все 8 датасетов подключены; теперь — вглубь
    • До 100–150 задач на датасет, партиями по уровню
    • Твоя ревизия выборки из каждой партии

    Уже: все 8 датасетов (Sakila, Chinook, Northwind, Employees, AdventureWorks, Airlines, Lahman, Delivery) и 574 задач на всех 5 уровнях; идём вглубь партиями по самым слабым темам. Northwind и AdventureWorks сконвертированы из официальных скриптов Microsoft для SQL Server; Employees — согласованная выборка после официальной проверки целостности; Airlines — выборка из дампа PostgreSQL от Postgres Pro (каждое 200-е бронирование); Lahman — официальные CSV SABR, только основные лиги; Delivery генерируется в браузере, а MySQL получает копию тех же строк. Покрыты все 53 темы (блокировки — на примерах FOR UPDATE SKIP LOCKED, NOWAIT и REPEATABLE READ). Готово, когда: ≈ 1 000 задач (было 1 200; на место OpenFlights и Olympics нужны две базы с коммерческой лицензией), каждая тема покрыта минимум 15 задачами.
